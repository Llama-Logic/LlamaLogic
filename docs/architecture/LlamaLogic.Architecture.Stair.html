Remarks

Each stair is also a lot object: ObjectId is the id of its object in LotObjectsSection.

Before version 7, a stair holds a second position and its bottom level (LegacyX, LegacyZ, BottomLevel) ahead of AnchorX, AnchorZ and TopLevel, and no stages: the game derives one stage from the distance between the two positions and computes TopElevation while loading. Versions 7 through 9 hold exactly one stage and versions 10 and later a 16-bit stage count. Before version 8, Flags is stored as separate Booleans (four, or six from version 6 on).

Flags

public ushort Flags { get; set; }

Property Value

ushort

Remarks

Before version 8, bits 0 through 3 (and bits 4 and 5 from version 6 on) are stored as Booleans, and the other bits cannot be stored. The game recomputes bits 4 and 5 while loading when Unknown1 is set, and sets bits 11 and 12 when bit 0 is set and LastStep is 65,535; the meaning of the bits is otherwise unknown. Changing the railing in game set bits 0x0001 and 0x1800 together with RailingKey (in-game test).

TopElevation

Gets/sets the elevation at the top of the stair

public float TopElevation { get; set; }

Property Value

float

Remarks

Present from version 7 on. The game places each stage's start at this elevation minus the steps above it times the step height; this value minus 0.25 per step is the bottom elevation in most lots examined (hypothesis: the step height is 0.25). Raising the walls of the stair's level from 3 m to 5 m changed it from 3 to 5 and the total step count from 12 to 20 (in-game test).
