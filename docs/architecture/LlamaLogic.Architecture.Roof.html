Remarks

From version 10 of the section on, a roof holds an InnerVersion, the bounding box of its footprint, the four corners of its footprint, Direction, Pitch, Curvature, four more floats (inner version 3 and later), BaseElevation, four per-side bytes (one byte copied to all four before inner version 2) and Flags. Before version 10, a roof holds only the bounding box (as two three-byte points), Direction, one per-side byte copied to all four, Curvature, Pitch and, in version 9, BaseElevation; the game derives the corners and computes the base elevation of older roofs while loading.

The game replaces each key whose catalog resource is missing or invalid with the default of its type while loading.

Property Value

Remarks

Present in version 9 and from version 10 on. When it is outside the valid range, the game recomputes it while loading as the elevation of the roof's level plus the lot's LevelElevationOffset (levels 0 and up) or NegativeLevelElevationOffset (levels below 0). Raising the walls below a roof from 3 m to 5 m changed it from 3 to 5 (in-game test).

The game rotates it in steps of the eight-way enumeration (modulo 8); it is 0, 2, 4 or 6 in every lot examined. Turning a gable roof 90° in game changed it from 0 to 6, two steps of the enumeration (in-game test). That it is the direction of the roof's ridge is a hypothesis.

InnerVersion

Gets/sets the version of the roof's own layout

public uint InnerVersion { get; set; }

Property Value

uint

Remarks

Present from version 10 of the section on; for older sections it keeps its default, 3, and encoding throws if it is changed. The game writes 3 and its reader reads any value, laying out the roof as for 3 when the value is 3 or more; this library supports 0 through 3. In the lots examined the roofs of version 11 sections hold 2 and those of version 13 sections 3; no version 10 or 12 section examined holds roofs. Inner version 3 holds Unknown1 through Unknown4, which encoding a lower inner version requires to keep their defaults; before inner version 2, a single per-side byte is stored and copied to Unknown5 through Unknown8.

Property Value

ResourceKey

Remarks

In-game tests show that the shape is this product alone: replacing one shape with another changed only this key and the per-side bytes Unknown5 through Unknown8. The instances seen are 0x144D (gable), 0x1B03 (half gable), 0x144F (hip), 0x29DC (half hip), 0x282AD (octagonal), 0x282B8 (cone) and 0x7DD4 (the catalog's diagonal gable).

Unknown5

Gets/sets the first per-side byte

public byte Unknown5 { get; set; }

Property Value

byte

Remarks

The four per-side bytes are 0 through 12 in the lots examined, and 0 through 3 in roofs of sections before version 13. In in-game tests they were 1, 1, 1, 1 for the gable, half gable and diagonal gable roofs and 0, 0, 0, 0 for the hip, half hip, octagonal and cone roofs, and replacing one shape with another changed only these bytes and RoofKey; that they choose gable or eave per side is a hypothesis, and their meaning is not proven. Before version 10 and before inner version 2, a single byte is stored, so the four must be equal to be written.
