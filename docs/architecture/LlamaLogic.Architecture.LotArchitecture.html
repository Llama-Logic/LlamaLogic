Remarks

The game stores a lot's architecture as a RecordBundle in three places: the WorldLotArchitecture resources of world files, the architecture data of each lot in a save game (see ZoneArchitecture) and tray blueprints (see Blueprint). Each record of the bundle is one section, keyed by its LotArchitectureSectionType, group 0 and instance 1.

Many sections can only be read with the lot's dimensions, which the LotSize section gives, so the bundle, not the section, is the unit of decoding. Records Decode(RecordBundle) cannot turn into sections are kept, unchanged, in UndecodedRecords: those of types this library does not know, those with another group or instance, those with a version (of the section or of an element of it) or a floor feature layer type this library does not support, and those that need dimensions an older LotSize section does not give (the game itself discards those).

Encode() writes the sections in the layout of their versions, so decoding and encoding the architecture of any lot the game wrote reproduces it byte for byte.

Where the documentation of the sections speaks of the lots, sections or entries examined, it means the 2,919 lot architectures examined while developing this library, at the game's patch level as of October 2026: those of the lots of the game's installed world files (of which twelve base-game worlds had been replaced by a community lot-replacement mod), the 179 lots of the Maxis originals of those twelve worlds, the lots of four save games and 73 tray blueprints.

GetManifestKeys()

Gets the keys the sections reference, in the order the game's saver would collect them into the ResourceManifest

public IReadOnlyList<ResourceKey> GetManifestKeys()

Returns

IReadOnlyList<ResourceKey>

Remarks

The game builds the manifest by recording every key it writes while saving the sections that precede the manifest, in its fixed save order, skipping repeats. This method does the same with the current sections, so assigning the result to a new ResourceManifestSection keeps the manifest consistent after edits. No code in the game's simulation library reads the manifest back (other parts of the game were not examined). For 2,907 of 2,912 lots in the game's world files, save games and tray blueprints examined, the result equals the stored manifest; the exceptions are lots of older world files whose blocks hold inline keys, which the current game no longer writes, and one saved lot whose stored manifest lacks two keys its sections reference.
