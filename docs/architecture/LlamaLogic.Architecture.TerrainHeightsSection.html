Remarks

The layout depends on the lot's Version; the section has no version of its own. First come VertexGridCount grids of (SizeX + 1) × (SizeZ + 1) 32-bit floats, one per tile corner, stored as SizeX + 1 rows of SizeZ + 1 values. Then, when HasWaterLevels, four 32-bit integers per tile, one per FloorQuarter, the tiles stored as SizeX rows of SizeZ.

When the lot's Version is less than 10 there is one vertex grid per level, indexed by level − LowestLevel, and the game skips all but the ground level's grid, which holds the terrain height. From version 10 there are two: grid 0 is the terrain height (the game's terrain height getter and setter use it, and in-game tests show that sculpting the terrain changes only this grid) and grid 1 is a second per-corner grid whose role is unknown; in-game tests with the raise, flatten and smooth tools changed only grid 0 and left grid 1 unchanged. The water levels are present from version 12; before it the game fills them with −400, which means no water.

Remarks

−400 (the game's default) means no water, and the value is −400 almost everywhere. The game multiplies it by 0.25 and uses the result minus the floor or terrain height as a water depth. In the lots examined it differs from −400 on every quarter of every pond and then equals the pond's WaterLevel; raising a pond's water level one step in game changed it from −3 to −2 on every quarter of the pond together with WaterLevel (in-game test).
