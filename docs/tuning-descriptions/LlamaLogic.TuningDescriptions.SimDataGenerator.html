Remarks

Which tunables become columns, the columns' types, and the values written for tuning that omits a tunable all come from Descriptions.

Some of what Maxis' build knows is not in tuning descriptions, so the generator learns it:

  • AddTuning(XDocument) and AddTuning(CombinedTuningModel) learn the entries of dynamic enumerations (such as tags defined by module tuning) and the instances of tuning that is referenced by name
  • AddLayouts(SimDataModel) learns the column order of schemas the game reads with a layout of its own (such as Client_* and Renderer.* schemas), whose columns are otherwise ordered by name

Maxis' build also converts some resource keys: a PNGImage key in tuning is written to SimData as a DSTImage key, and an AudioConfigurationReference key as an AudioConfiguration key in group 0x001407EC. The generator does the same unless RemoveResourceKeyConversion(ResourceType, uint) says otherwise, and AddResourceKeyConversion(ResourceType, uint, ResourceType, uint) adds conversions.

For the game's own SimData, the game's combined tuning and SimData are the sources of what the generator needs to learn.
